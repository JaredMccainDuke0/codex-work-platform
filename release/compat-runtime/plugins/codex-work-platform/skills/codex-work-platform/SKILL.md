# Codex Work Platform

This local compatibility-runtime skill declares the product boundary. Business state belongs to the local control kernel, not chat text. Call `entry_capabilities` and `platform_status` before mutations, use `project_bootstrap` for the complete four-object project creation Saga, and reuse idempotency keys on retries. Chat, file and import observations must first use `change_candidate_submit`; only `change_candidate_decide` with an explicit approval may change a formal TASK or TODO.

Use `project_brief_read` for the selected project's explanation page. Formal goals come from TASK `objective` and `completionCriteria`; formal steps come only from TODO `parentTaskId` and LONG_TASK `taskId`. Do not duplicate task state in brief artifacts or guess an owner for unassigned work. Use `project_brief_record` only for decisions, owner statements, pitfalls, and short narrative supplements. Record at most the current user turn plus verified kernel objects or events; never scan or copy full chat history. One request may contain 1–50 source-bound records and must reuse one stable idempotency key on retry. A Codex-turn quote remains `PENDING_VERIFICATION`; do not claim it is verified. Decisions must keep decision state separate from application state, and `APPLIED` must name the exact formal object version. Superseding corrections must extend the current same-project, same-task, same-section leaf. Quotes stay hidden unless the local user explicitly reveals them with the control-page capability.

At a task start, material decision, user correction, or task close, add only the newly established explanation facts from that bounded turn. Keep summaries concise, exclude credentials and unrelated personal data, and use formal TASK/TODO/LONG_TASK mutations for status or ordering changes. Missing or conflicting sections remain visibly incomplete; do not fill them by inference.

Use `context_pack_publish` to create an immutable minimal Context Pack and `context_pack_current` to verify its binding and indexed file hashes. Never pass full chat or transcripts. Use `project_recover_task` to create a separate recovery task without replacing the main task. `project_backup` and `project_restore_backup` are the only supported cross-workspace backup path; restore targets must be new paths and are verified before mutation.

For staged work, call `long_task_create` with a finite retry, duration, token and cost policy, then call `long_task_run`. `long_task_status` verifies the immutable checkpoint chain. Use `long_task_resume` only to acknowledge an explicit `WAITING_USER`; use `long_task_takeover` for operator intervention. Never treat `RUNNING` or `BACKOFF` as completion, bypass the lease, rewrite checkpoint files, or retry beyond the frozen policy. Only `COMPLETED`, `WAITING_USER`, `MANUAL_INTERVENTION` and `FAILED` are terminal.

For external evidence, `public_search_run` is the only search entry. It requires the hard enable switch, `PUBLIC_WEB` data scope, a domain allow-list and frozen query/result/cost budgets; only an `env:VARIABLE_NAME` credential reference may be stored. Search output is immutable evidence, never approved knowledge. Use `knowledge_candidate_submit`, then `knowledge_candidate_decide`; resolve every detected conflict before approval. `search_evidence_refresh` must be used when upstream content changes so dependent candidates and declared downstream objects become visibly stale. These operations never write a core knowledge base.

For official information, create a local consent with `official_import_consent_create`. Consent can only be reduced with `official_import_consent_restrict`; revoke or delete it with `official_import_consent_close` before any later import. `official_information_import` accepts only an inline user-provided package or one file inside an explicit local allow-root. It does not access mail clients, browser sessions, OAuth or remote connectors. Imported records are redacted `OFFICIAL_INFO_CANDIDATE` objects. `official_information_candidate_decide` records an explicit local approval or rejection but never writes tasks, todos, knowledge or a remote source. Use `official_information_projection` for the matching consent and audit trail.

Entry A is unavailable without a registered App ID; use B or C. This is a local bundled runtime, not a public Plugin-directory release. Installation, upgrade, diagnosis, backup, restore and uninstall must use the bundled installer so the active Codex home, destructive deletion and unverified state migration remain forbidden.
